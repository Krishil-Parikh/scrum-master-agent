# AI Agile Software Development Pod

A working MVP of the system described in [`PRD — AI Agile Software
Development Pod.md`](<./PRD — AI Agile Software Development Pod.md>) and
built following [`AI Agile Software Development Pod — Phased MVP
Roadmap.md`](<./AI Agile Software Development Pod — Phased MVP
Roadmap.md>): a Scrum Master agent coordinating six specialized developer
agents (Frontend, Backend, AI/ML, DevOps, MLOps, Database) through a real
Agile workflow — independent requirement analysis, Business SME
clarification, Agile planning, parallel development on isolated Git
branches, a genuine cross-agent merge conflict resolved through agent
communication (not "ours"/"theirs"), code review, testing, sprint review,
and retrospective — against a project brief you provide, live, on a real
OpenRouter-hosted Mistral model.

This isn't a mockup of that idea. `backend/scripts/run_demo.py` runs the
entire loop end to end against the real API and produces real Git commits
and a real, browsable Markdown project history — see
`backend/README.md` for a sample of what one run actually produced.

## Layout

```
backend/     FastAPI service: agents, orchestration, Git layer, memory, API
frontend/    React + TypeScript dashboard -- the live view into a running pod
```

Each has its own README with setup instructions
(`backend/README.md`, `frontend/README.md`). Short version:

```bash
# Terminal 1 -- backend
cd backend
python -m venv .venv && .venv\Scripts\activate      # or: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # fill in at least one OPENROUTER_API_KEY_1
uvicorn app.main:app --reload --port 8000

# Terminal 2 -- frontend
cd frontend
npm install
cp .env.example .env.local
npm run dev
```

Then open `http://localhost:5173`, create a project from the
"Start a new project" prompt (or `Settings`), and watch the pod work.

Or skip the UI and run one full project end to end from the CLI:

```bash
cd backend
python scripts/run_demo.py
```

## What's actually implemented

Everything in the Roadmap's phase list through **Phase 18** (the MVP
Demonstration Project) is real and working, not stubbed:

- **Project intake** (Markdown/TXT/PDF/DOCX) → a structured
  `ProjectContext`, persisted as both JSON and human-readable Markdown.
- **7 real agents** (Scrum Master + 6 developers), each with its own
  identity, system prompt, and primary skill — backed by a shared skill
  library any agent can dynamically load outside its own specialty.
- **Independent multi-agent requirement analysis**, consolidated into
  questions for a **Business SME session** (a human via the API/UI, or an
  LLM playing the SME for unattended runs).
- **Agile planning**: Epics → Stories → Tasks with dependencies and
  risk, generated by the Scrum Master and turned into a Sprint.
- **Real Git branch isolation** via `git worktree` — six actual branches,
  six actual working directories, real commits.
- **Cross-agent dependency sync** (one agent's branch merged into
  another's when its task depends on completed work) and a **deliberate
  merge-conflict drill** resolved by an agent reasoning about both sides'
  intent, not a blind `git checkout --ours`.
- **Cross-specialty code review**: a "buddy" agent loads the author's
  skill and reviews the diff before a task is marked done.
- **Stand-ups, sprint review, and retrospective**, all genuinely
  generated from what happened in the run, not templated filler.
- **Persistent project memory**: `PROJECT.md`, `REQUIREMENTS.md`,
  `AGILE.md`, `STANDUPS.md`, `SME_DISCUSSIONS.md`, `DECISIONS.md`,
  `DEVELOPMENT_LOG.md`, `GIT_ACTIVITY.md`, `RETROSPECTIVES.md` — browsable
  live from the frontend's Project Docs page.
- **A live dashboard**: agent roster with real-time state, the full
  conversation feed, a live terminal of actual git/test output, the
  backlog/Agile board, Git branches and commit history, and an SME
  question modal — all fed by one WebSocket off the backend's event bus.

Deliberately out of scope for this MVP (see the Roadmap's own "Final MVP
Boundary" and the PRD's Non-Goals): dynamic agent spawning beyond the six
specialties, autonomous production deployment, and a security/QA-agent
layer — the roadmap explicitly defers these to a post-MVP phase once the
core loop above is validated, which is what this build demonstrates.

## Design notes worth knowing before you read the code

- **The demo project's Git repo is separate from this repo.** The pod
  builds its target project (e.g. a task-management app) in
  `backend/workspace/<project_id>/` — a fresh, independent Git repository
  the pod creates and commits to. It is not nested into or pushed to
  *this* repository's history.
- **Every layer is decoupled on purpose**: agents don't import FastAPI,
  the Git layer doesn't know about agents, the event bus doesn't know
  about the frontend. `backend/app/orchestration/orchestrator.py` is the
  one place everything is wired together — read that first.
- **OpenRouter key pool**: the backend rotates across every
  `OPENROUTER_API_KEY_N` you configure, failing over past rate limits,
  auth errors, or an individual key running out of credit, so one bad key
  doesn't take the whole pod down.
